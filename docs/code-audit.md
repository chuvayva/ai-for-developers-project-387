# Еженедельный аудит кода: выводы

## Что потребовало уточнений

1. **Агент и модель.** Образец задачи был написан под OpenCode и секрет `OPENCODE_API_KEY`. В репозитории такого секрета нет, поэтому воркфлоу использует `anthropics/claude-code-action` и тот же `CLAUDE_CODE_OAUTH_TOKEN`, что `claude.yml` и `pr-review.yml`. Первая версия не задавала модель, как и остальные воркфлоу. PR #10 добавил выбор модели при ручном запуске, по умолчанию `claude-sonnet-5-5`. Еженедельный запуск берёт ту же модель.
2. **Где хранить результат.** Первый план писал отчёт только в Job Summary и артефакт. По образцу задачи результат перенесли в GitHub Issues: отдельное issue на каждую новую находку и одно постоянное issue «Code audit log». Job Summary остался. PR #10 вернул артефакт с отчётом и журналом агента.
3. **Права.** Образец давал `id-token: write` для обмена токена через GitHub App. Вместо этого воркфлоу передаёт агенту `github_token: ${{ github.token }}` с двумя правами, `contents: read` и `issues: write`. Агент работает от имени `github-actions[bot]`.
4. **Расписание.** Вместо `17 9 * * 1` из образца выбран понедельник 06:00 UTC (09:00 по Москве).
5. **Регистр меток.** Первая версия промпта просила искать «слова TODO, FIXME и HACK» и не указывала регистр. Инструмент Grep по умолчанию учитывает регистр, поэтому `// todo:` агент бы пропустил. Промпт теперь задаёт шаблон `\b(TODO|FIXME|HACK)\b` с флагом `-i`. Проверка этого шаблона на тестовом `todo:` в `server/src/main.ts` прошла (прогон 45241868803).

## Что изменено в настройках и постановке задачи

- Одновременно идёт только один аудит (`concurrency: weekly-code-audit` без отмены). Job ограничен 15 минутами, агент 40 ходами.
- Агенту разрешены только `Read`, `Glob`, `Grep`, `gh issue list/view/create/comment` и `gh search issues`. Write и Edit не разрешены, поэтому менять файлы он не может.
- За один запуск агент создаёт не больше 5 новых issues. Остальные находки попадают только в журнал. Этого ограничения не было в образце, оно защищает трекер при первом запуске на большом количестве TODO.
- Промпт велит считать комментарии в коде и тексты issues данными, а не инструкциями.
- Отчёт в Job Summary пишет отдельный шаг с `if: always()`. Если агент упал или не вернул отчёт, шаг запишет «аудит не завершён» со ссылкой на лог.

## Что осталось учесть

- Правило «комментировать только журнал» держится на промпте. `Bash(gh issue comment:*)` разрешает комментарий в любом issue. Комментарий в коде с внедрённой инструкцией в худшем случае даст спам в issues этого репозитория. Больше токен ничего записать не может.
- Issues, которые создал `GITHUB_TOKEN`, не запускают другие воркфлоу. Job `triage` в `claude.yml` их не разбирает, метки ставит мейнтейнер.
- `workflow_dispatch` работает только с файлом из `main`. Ручной запуск можно проверить лишь после merge.
- Тестовый комментарий в `server/src/main.ts:3` и issue #12 нужны только для проверки. После неё комментарий нужно удалить, а #12 закрыть. Следующий аудит запишет в журнал «найдено: 0».
